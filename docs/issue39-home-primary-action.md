# Issue #39: 状況に応じたホーム主アクション

回答中のセッションがあるときは、ヒーローを「中断中の学習／続きから再開」に切り替える。元の学習対象を使ってresumeを呼び、別セクションの再開ボタンを除去する。ホームのフィルター内件数を中断セッションの枚数として表示しない。

HomePrimaryActionとStudyStore.homePrimaryActionに主アクションを集約。セッションなしでは復習→新規→カード追加／学習不可の順に選ぶ。新規は既存の日次枠・兄弟カード制限に従う。別の学習開始は副操作に限定し、既存の切替確認を使う。

出題のないセッションは短期復習の待機時刻または完了を表示する。ホーム更新で元のセッションのキューを再確認し、期限到来後は同じセッションを再開する。完了は出題がないことを保存直前に再確認してSessionDraftを終了する。確定済み履歴・FSRS・due・設定・バックアップ形式は変更しない。完了によって、そのセッションのUndoは終了する。

## PR #44 レビュー修正: 待機更新の保存削減

従来はホームの15秒更新ごとに、空セッションへresumeとsetSessionActive(false)を呼び、それぞれ保存していた。出題がない場合でもupdatedAt等を書き換え、次のキューを再計算していた。

修正後は、空セッションに出題できるカードがあることを読み取りで確認したときだけ、カード選択と非アクティブ状態の設定を1つのトランザクションで保存する。出題がない場合はモデルを変更せず、保存を呼ばない。保存失敗時は既存のrollbackで元の空セッションとUndoを保持する。

固定15秒ポーリングを廃止し、全デッキの次の復習期限と学習日の終端のうち早い時刻にtaskを予約する。期限・設定が変われば予約を作り直し、ホーム非表示・バックグラウンド・学習画面表示中はキャンセルする。ホームの表示、タブ切替、フォアグラウンド復帰でも再判定する。ホームと異なる元スコープの短期復習も全デッキの期限に含まれる。

キューの計算式は維持し、判定に使用する履歴の取得を当該学習日分へ限定した。FSRS、日次新規枠、兄弟カード制限、保存スキーマ・バックアップ形式は変更していない。

保存回数の結合テストで、待機中と回答下書きの保持は0回、期限到来と学習日切替は各1回を確認。保存失敗→フォアグラウンド復帰による再試行、別のホームフィルター、元のセッションID／スコープ／Undo／確定履歴の保持も検証する。3000枚・1万履歴の同一データで従来経路と修正経路の時間と保存回数を比較する。

単体／結合84件は失敗0、既存1件スキップ。3000枚・1万履歴の更新5回で修正後の保存0回、従来のresume→setSessionActive→presentation→homeSnapshot経路は10回。平均更新時間は修正後0.158秒、従来経路0.232秒（単発Simulator比較、実機・バッテリーの測定ではない）。従来経路のresumeも共通の最適化済み履歴読み込みを使うため、保存削減の比較を保守的に評価している。

ホームで操作せずに短期復習の期限を待つUIテストを追加し、自動で再開可能になることとUndo保持を確認した。途中のUI実行は他PRの同一Simulatorへのインストールと競合したため、こちらの実行のみ停止し、専用Simulatorで再実行した。PR #45・#46のコードや実行には変更を加えていない。

最終Debugビルドと単体／結合84件、関連UI8件が成功（失敗0、単体／結合の既存1件スキップ）。結果は/private/tmp/anki-pr44-refresh-benchmark-final.xcresultと/private/tmp/anki-pr44-refresh-ui-final.xcresult。実機の操作、VoiceOver音声、実際のバッテリー消費・物理ディスクI/O量は未測定。
