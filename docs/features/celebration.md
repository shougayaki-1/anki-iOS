# 学習成果の全画面セレブレーション（Issue #103）

## 画面と演出

専用SwiftUI `CelebrationView`をネイティブfullScreenCoverで表示する。初回は青緑の朝日と穏やかな光、連続学習は炎と直近7日の実際の正式回答記録、3/7/14/30/100日の節目は橙色の炎と月桂樹、日次目標は青い進捗リングとトロフィー、長期定着は緑の葉と花を使う。数字、見出し、達成根拠、達成日をこの順で読む。

0–350msで主役が現れ、400msから数字を表示して既存HapticsServiceの成功触覚を1回呼ぶ。通常日は650ms、節目は900msから光・リング・花が反応し、約1秒〜1.5秒で静止する。数字は保存された達成値を表示し、架空の「直前の値」は作らない。BGM・効果音・ループ演出はない。off/standard/richは既存サービスに従う。Reduce Motionは最初から全情報を静的に表示する。バックグラウンドでは静止状態に進め、復帰時に演出・触覚を再生しない。

主要操作と「記録を見る」は下部のsafeAreaInsetに置く。スクロールは内容が収まらない場合の逃げ道とし、操作を下まで探す必要はない。閉じるボタンは演出中も有効。標準背景・フォント・SF SymbolsによりLight/Darkに対応する。装飾はVoiceOverから除外し、数字と単位を結合、7日列には日付と学習状態を付ける。

## 表示タイミング

- #202の保存後通知 `studyAchievementEventsAvailable`では、評価操作を覆わない短時間の非阻害表示のみ。全画面もclaimも行わない。
- 最後の回答後も既存の終了画面とUndoを残す。`completeSession`の保存成功後、ReviewViewのfullScreenCoverのonDismissで未表示イベントをclaimし、全画面を1回提示する。
- 回答上限の到達、または現在の出題を終えた `.complete` が自動表示の対象。上限なしも出題を終えた場合は同じ。回答上限と日次目標は別。
- 待機・対象なし・設定変更のための終了、閉じるによる中断、再開、再起動、単なるフォアグラウンド移行では自動表示しない。ホームの「今日の達成を見る」から明示的に確認できる。過去日の未表示イベントも達成日を明示してまとめて確認する。
- 「もう1セット」は既存の再開始とUndo保護を維持する。先に続けた場合のお祝いは次の正常終了またはホームの導線まで延期する。
- 終了保存失敗では学習画面とUndoを維持し、claimしない。回答保存失敗のイベントは基盤が生成しない。Undoでは基盤が未表示イベントを取り消し、通知も消す。

## 統合と永続化

主役の優先度は、特別な連続節目、長期定着の節目、日次目標、通常の連続学習、今日初回の順。1日目の連続と初回は初回だけを表示し、2日以上の連続があれば同日の初回は省略する。表示を省略した重複意味のイベントもclaimして再表示を防ぐ。他の実績は同じ画面の「一緒に達成しました」に置く。

未表示候補を既存 `pendingAchievementEvents()` から取得し、個別の `claimAchievementEvent(id:now:)` が成功したものだけで画面を構成する。既にclaim済みならnilとして除外する。途中の保存失敗ではそれ以前にclaimできた実績だけを1画面で表示し、失敗したものと後続はホームに残す。最初のclaimが失敗した場合は画面を出さない。まとめてclaimする新規トランザクションや判定・スキーマ変更は導入しない。

#202の高々1回仕様に従い、**claim保存後、実際の表示までにプロセスが終了した場合は未視聴でも再配信しない**。displayedAtは視聴完了・閉じた時刻ではなく「表示権を確保した時刻」。中断中の明示的な確認でclaimした実績は、その後Undoしても過去の表示履歴として残る。未表示の実績はUndo後の再取得で除外される。

「ホームへ」と閉じるはカバーを閉じる。「学習を続ける」はホームの既存おすすめ・再開が可能な場合だけ表示し、カバーのonDismiss後に既存 `startRecommended()` で候補と保存済みセッションを再検証する。「記録を見る」はカバーを閉じて記録タブの既存達成履歴へNavigationStackで遷移する。カバー表示中に新規セッションを開始しない。

日次目標はイベントのvalue/threshold（ユニークカード数）を表示し、回答回数から計算しない。長期定着はReview状態・FSRS Stability >= 21日の推定であり、永久記憶を保証しない。

## 検証用画面

Debug限定 `-study-test-store <UUID> -study-test-celebration <first|normal|milestone|goal|mature|multiple>` で分離したUITestStoresに表示専用fixtureを作る。正式な判定・claimの検証はメモリストアのIntegrationテストで行う。fixtureは本番ストア指定時・Releaseビルドでは利用できない。

## 検証結果（2026-10-14）

iPhone 15 Pro専用Simulator（iOS 26.5）でDebugビルドと関連11 Integrationテスト・2 UIテストが成功。全テストは実行していない。メモリストアまたは専用UITestStoresのみを使用した。

- 初回・通常12日・7日節目・目標20枚・長期定着100枚・複数統合の6画面、閉じる、記録履歴への遷移、大きなボタンの幅/高さをUIテストで確認。
- 実際の4枚の学習で3枚目の目標達成から継続、中断、プロセス終了/再起動、再開、Undo、最後のUndo維持、正常終了、全画面、バックグラウンド/復帰、履歴、再起動後の非再表示を確認。
- 関連Integrationテストで回答保存/終了保存失敗、claim失敗・部分成功・重複、未表示の再取得、長期定着Undo、無制限、短期復習待機、対象0枚、上限未達でも出題終了、続行時の新規セッションが1つだけであることを確認。
- Reduce Motionは初回画面で静的表示、Darkは長期定着画面で確認。接続実機の本番アプリは操作していないため、物理触覚・実機の操作感・VoiceOver実読み上げは未検証。
