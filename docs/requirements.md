# 個人用iPhone暗記アプリ — 実装要件定義書 v1.0

- 作成日：2026-10-08
- ステータス：実装開始用ドラフト（利用者との会話で合意した項目と、実装を進めるための暫定初期値を区別）
- 対象：個人用のiPhoneネイティブアプリ
- 開発：Swift / SwiftUI / Xcode / Codex

## 0. 目的・設計原則

学習内容を素早く登録し、FSRSに従って適切なタイミングで復習できる、ローカルファーストの暗記アプリを作る。画面はApple純正アプリらしいネイティブUIを優先し、Duolingo風の気持ちよい触覚と控えめなアニメーションを学習画面に組み込む。

**確定した原則**
- iPhone専用、SwiftUIネイティブ。WebViewベースのUIは採用しない。
- 個人利用。アカウント、サーバー、常時インターネット接続不要。
- データと画像は原則端末内に保存。バックアップはファイルに手動エクスポート／インポート。
- 記憶スケジューラーはFSRS-6、回答は4段階の自己評価。
- 4種類のカード：一問一答／記述式／穴埋め／画像・図表。
- 回答方法：頭の中で回答、テキスト入力を両方サポート。カードごとに初期値を設定、学習中にも一時変更可。
- 登録経路：手入力／CSV等ファイル／文章貼り付け／写真・スクリーンショット。
- デッキは階層型、タグはデッキと独立。学習対象をデッキとタグで絞り込める。
- 「復習」「新しく覚える」「復習＋新規」の3モード。
- 復習枚数は無制限。毎日の目標は任意で、達成しても学習を続行可能。
- 通知は「復習が必要な日だけ」、時刻指定のローカル通知（初期設定オフ）。

**実装時の初期値（変更可能）**
- Deployment target：iOS 17以降
- 目標保持率：90%（設定範囲 80〜97%）
- 1日の新規カード：10枚
- 1日の学習目標：20枚（無効化可能）
- 学習日の切替時刻：現地時間の午前4:00
- 通知時刻：20:00
- 復習出題順：期限が古い順。同期限帯ではランダム
- 同じノート由来の関連カードは同日出題を抑制：オン
- 触覚：標準

## 1. 対象外（初期リリース）

- クラウド同期、独自バックエンド、複数ユーザー、公開問題集の共有
- 自動的なAI問題生成・記述式AI採点
- 大規模な個人データに基づくFSRSパラメータのオンライン最適化
- Excel `.xlsx` の直接読込（CSV/TSVへ変換して読み込む）
- Anki `.apkg` のインポート
- Apple Watch、iPad最適化、Android、Web版
- iOSがアプリを起動していない間の継続的なバックグラウンド再計算への依存

## 2. アプリ構成・画面

メインタブは4つ。

1. **ホーム**：今日の復習待ち・新規カード残数・学習目標の進捗、「復習する」「新しく覚える」「復習＋新規」の入口。
2. **ライブラリ**：階層デッキ、タグ、検索、カード一覧、詳細、編集。右上の「＋」から登録を開始。
3. **記録**：日次学習枚数、回答回数、継続日数、自己評価の内訳、予測保持率などの統計。
4. **設定**：学習目標・FSRS・通知・触覚・学習日境界・バックアップ。

学習画面は集中しやすい全画面表示。標準の`TabView`、`NavigationStack`、`List`、`Form`、`sheet`、`toolbar`を優先。システムフォント、SF Symbols、Dynamic Type、VoiceOver、ダークモード対応。Reduce Motion時は派手な移動アニメーションを抑える。

### Phase 6のアイデンティティとUI監査（Issue #4）

表示名は「暗記ノート」、アクセントはインディゴ、アイコンは独自のカード＋復習の図形を使用する。Bundle ID・保存データの同一性は維持する。ライト／ダークのアセット、評価ボタンの文字コントラスト、未保存デッキ追加のキャンセル、検索結果ゼロの案内を整備する。判断と検証範囲は `docs/native-ux-audit.md` に記録する。公開時の名称・ストア情報の最終確認はIssue #21で行う。

### Phase 6の学習表示・スワイプ（Issue #5）

設定から文字サイズ、通常画像の表示、答え表示後の問題／解答順、アニメーションを変更できる。Dynamic Typeを保持し、Reduce Motionを優先する。画像マスクは画像を非表示にしない。スワイプ初期値はOFF。ON時の専用操作領域だけで右へ答え表示、表示後は左Again／下Hard／右Good／上Easyを行い、短い動き・斜め・戻す動き・カード切替中・短時間の連続操作を確定しない。VoiceOver利用時は既存ボタンを使用する。追加設定JSONの任意項目に保存し、旧データの標準表示と全UUID・FSRS・ReviewLogを保全する。詳細は `docs/review-customization.md`。

### Phase 7の一括管理（Issue #6）

ライブラリの複数選択からデッキ移動、タグ追加／除去、停止／再開、確認付き削除を行う。停止／再開は選択カードのみ、移動・タグ・削除はノート単位で兄弟カードも対象とする。変更件数・対象・兄弟カードの範囲をプレビューし、確定までの対象変更を検出する。単一保存とrollbackで部分成功を防ぎ、非削除操作はUUID・FSRS・期限・履歴を保持する。削除後も過去の回答履歴を保持する。本文の一括置換は含めない。詳細は `docs/bulk-management.md`。

## 3. コンテンツ管理・デッキ・タグ

- `Deck` は親デッキを持てるツリー構造。子孫を含むデッキ単位で学習可能。
- `Note` は1つの所有デッキに属する。各 `Card` は親Noteを通じて所属を判断する。
- `Tag` はデッキと独立し、複数のNoteに関連づけられる。
- 検索は問題文・解答・デッキ・タグを対象にする。
- デッキ名変更・移動ではNoteやReviewLogを失わない。
- デッキ削除は明示的な確認が必要。子孫・Noteをまとめて削除するか移動するかを選択させる。
- Cardの一意性は `noteID + variantKey` で定義し、表示順序の変更でカードIDが変わらないようにする。

## 4. Note種別とCard生成

**一問一答 (`basic`)**：表面、解答、任意の解説・画像。基本1Note→1Card。任意で裏表反転カードを追加できる設計にする。

**記述式 (`written`)**：設問、模範解答、任意の解説・画像。基本1Note→1Card。

**穴埋め (`cloze`)**：元文章と `clozeID` で識別する複数の隠し箇所を保持。1つの穴→原則1Card。テキスト形式では `{{c1::語句}}` などの記法をサポート。テキスト編集後も既存clozeIDと学習履歴を保てるようにする。

**画像マスク (`imageOcclusion`)**：原画像のメディア参照と複数のマスク矩形（原画像の座標系で正規化したx/y/width/height）、任意の解答文、maskIDを持つ。1マスク→原則1Card。「全マスクを隠し対象を強調」「対象マスクだけ隠す」を切り替え可。

兄弟カードは同日の連続出題を標準で抑制。ただし、短期再学習の予定が来ているカードは例外となり得る。抑制は出題キュー上の制御であり、FSRSのdueDateや状態を書き換えない。

### 任意の学習ヒント（Issue #47）

4形式とも、Note共通の複数行ヒントを解説とは別に任意登録・編集・削除できる。`TextContent.hint` / `NoteInput.hint` はOptionalで、キーのない旧JSON・下書き・完全バックアップも読み込む。contentPayloadのschemaVersion（1〜2）とSwiftDataスキーマ、Note/Card UUID、variantKeyは変更しない。

学習・出題プレビューでは解答前だけ「ヒントを見る／ヒントを隠す」で開閉し、初期は非表示。空欄なら操作を出さず、カード切替・中断再開・Undoで閉じる。回答下書き・画像マスクの遮蔽は保持し、FSRS・自己評価・学習時間・新規枠を自動補正しない。ヒントのみの編集では履歴初期化の確認を出さず、履歴・復習予定・カード生成数を保持する。`basic:reverse`では解答漏洩を避けて共通ヒントを表示しない。穴埋めの`{{c1::語句::ヒント}}`は従来のプレースホルダーとして独立して維持する。

CSV/TSVは任意ヒント列を指定でき、ヘッダー`hint`（大文字小文字不問）/`ヒント`を自動認識する。列なしの重複更新は既存ヒントを保持し、指定列の空欄は消去する。プレビューでヒントを編集でき、保持・置換・消去を表示する。OCRとQ/A貼り付けでは従来通り生成し、編集で追記する。

## 5. 学習と回答

- `ResponseMode`：`mental` / `typing` / `ordering`。
- `mental`：設問→思い出す→答え表示→4段階評価。
- `typing`：設問→任意の文章入力→自分の回答と模範解答の比較→4段階評価。
- 評価は `again`、`hard`、`good`、`easy`。`hard` は「思い出せたが難しかった」ときであり、誤答には`again`を使う説明をUIに表示する。
- テキスト回答はセッション途中での下書き復元に利用し、評価確定後の恒久的な回答ログには初期実装では保存しない。
- 回答モード変更は同一CardのFSRS履歴を維持する。
- 評価確定ごとにCardのFSRS状態更新とReviewLogの追加を1つの永続化単位として保存する。保存に失敗した場合は成功として画面を進めない。
- Undoは直前の評価について、保存前のFSRSスナップショットと履歴を使い安全に復元する。Undo後は通知予定と学習キューを再計算する。
- 学習画面の中断・復帰時、未確定カードは採点されない。確定済みカードは保存済みの状態から復元する。
- 回答時間を測定しReviewLogに保存する。将来的な分析用であり、初期FSRS採点には無断で追加の重みをかけない。

### 英文並び替え（Issue #49）

一問一答・記述式では、既存の同じNote/Cardを`ordering`で回答できる。手入力・編集・下書き・プレビュー・CSV/TSV・バックアップで標準モードを保持する。モードを変更してもCard UUID、variantKey、FSRS履歴を作り直さない。学習中の切替はNoteの標準設定を変更せず、文字入力の下書きを保持する。

模範英文を空白で分割し、各語句に出現位置のIDを付ける。短縮形、ハイフン、Mr.などの略語、付随する句読点は同じチップに残す。判定はUnicodeの合成、英字の大小、語句の両端の句読点・引用符を正規化した順序で比較する。同じ正規化語は別のIDでも交換可能。原文・模範解答は変更しない。意味の近い別解をAIで採点せず、登録された語順だけをオフラインで比較する。分割・比較・操作状態はUIとスケジューラーから独立したドメイン型にまとめ、将来の別解追加に備える。

初期候補は重複語を考慮しても正解順にならないようシャッフルする。タップで選択し、選択済みをタップすると取消。最初からやり直せる。全語句の選択前は判定を無効にする。不正解は答えを隠したまま再挑戦でき、正解または答え表示で原文・解説と通常の4段階評価を出す。文字・アイコン・色で結果を示す。初回誤答または答え確認にはAgain、初回正解にはGoodを目安として表示し、最後は利用者が評価する。選択、取消、リセット、正誤判定だけではFSRS、ReviewLog、日次枚数を更新しない。明示的な評価確定だけで1回保存する。

2〜40語、全体600文字以内、各語48文字以内、空でない行は3行以内、英字を含むことを対象とする。記号だけの語句、正規化後にすべて同じ語、穴埋め・画像問題などは理由を表示して通常回答へ戻す。登録内容は消去しない。未対応入力の登録時は並び替え選択を無効にし、既存設定が未対応なら学習中だけ頭の中で回答へ戻す。

SwiftData V4は既存モデルの属性を変更せず、`OrderingDraftRecord`を1エンティティ追加しV3から軽量移行する。選択ID・候補順・初回正誤・試行回数・答え確認をバージョン付きJSONで保存し、中断・プロセス再起動後も戻す。Undoと次カードでは答えを隠した新しい下書きにする。内容を編集すると古い並び替えを破棄するが、ヒントだけの編集では保持する。完全バックアップの任意`orderingDrafts`で復元し、キーのない旧バックアップも受け付ける。未知のローカル回答方式はmentalへ戻す。バックアップの未知方式・不正ID・参照不一致は復元前に拒否し、現在データを保持する。

CSV/TSVは任意列`responseMode` / `response_mode` / `回答方式` / `回答方法`を自動認識、または手動指定できる。値はmental・typing・orderingおよび表示名を受け付ける。列を指定しない重複更新は既存方式を保持、明示空欄・未知値・未対応のorderingはmentalへ戻す。プレビューで方式を修正でき、フォールバック理由を表示する。従来のQ/A貼り付けと2列CSVは変更しない。

ヒントは判定前に従来通り開閉し、答え表示で閉じる。音声読み上げ機能は現在未実装。候補・選択済みチップは標準Buttonと44pt以上の操作領域、VoiceOver用の語句・位置・選択取消アクションを備える。候補の位置はシャッフル後の位置を読み上げ、正解順を漏らさない。折返し、最大Dynamic Type、ダーク、小型iPhone、Reduce Motionを検証する。

### 学習モードとキュー

- `review`：期限到来済みのReview/Relearning、および学習中の期限到来済みカードを処理。原則dueDate昇順。
- `new`：未学習Cardを1日の新規カード枠内で出題。セッション中に発生した短期学習・再学習ステップは処理できる。
- `mixed`：期限到来済み復習と新規を混在。標準は復習3：新規1（比率は内部設定可能）で、短期学習期限到来カードを優先。
- 1日の新規学習枠は全デッキ・全モード共通。復習の枚数上限は設けない。
- 日次目標の枚数は原則「その日に評価確定したユニークCard数」。回答回数は別途集計する。
- 期限が超過しているカードは翌日も未処理のまま残る。FSRS更新は実際の回答日時を利用する。
- 停止済みCard（suspended）をどのモードにも出題しない。

## 6. FSRS-6の統合

- `open-spaced-repetition/swift-fsrs`を第一候補に検証する。Swift Package Managerで依存を固定する。
- 現在のREADMEにあるように`FSRSDefaults.defaultWv6`相当の21パラメータを明示指定する。パラメータ省略時にFSRS-5相当になる構成を避ける。
- リリース`v5.0.0`の公開イシューに初期化子のアクセス制限に関する報告がある。最初の工程で実際のXcodeビルドを通すこと。問題があれば修正済みコミットへ固定、代替ライブラリ、または小さな互換ラッパーで対応し、採用理由を記録する。ビルド未検証のスニペットをそのまま実装しない。
- CardにFSRS状態（状態区分、dueDate、最終復習日時、安定性、難易度、復習・忘却回数など、利用ライブラリが要求する完全なシリアライズ可能状態）を保持する。
- Retrievability（現在の想起確率）は経過時間から計算する。固定値として保存しない。
- 目標保持率はアプリ設定とし、90%を初期値にする。変更後は次の回答から適用し、既存dueを一括で変更しない。全カードの再計算は別コマンドでユーザー確認の上実行する（初期版ではこのコマンドは後期Phaseでもよい）。
- 学習履歴は将来のパラメータ再最適化やスケジューラー再計算に備えて削除しない。

## 7. 登録・インポート

すべての入力経路が内部の`NoteDraft` / `ImportBatch`に正規化され、**プレビュー・修正・重複確認→明示的な確定→永続化**の一連の操作に合流する。

1. **手入力**：Note種別を選択し、設問、解答、解説、画像、タグ、標準回答モードを入力。保存して次へ、編集中の下書き自動保存、出題プレビュー。
2. **ファイル**：UTF-8 CSV/TSV/TXT、ヘッダー有無と列マッピングを選択可。最低限「問題」「解答」の2列で一問一答を生成。引用符内の改行／区切り／引用符エスケープ対応。未対応形式は理由を表示。
3. **貼り付け**：`Q:`/`A:`、タブ区切り、`{{c1::...}}`のcloze構文を解析。普通の文章はまず編集可能テキストに取り込む。AIなしに無理に問いを生成しない。
4. **写真・スクショ**：PhotosPickerとカメラ（権限は使用時に要求）、トリミング、VisionによるOCR、認識結果編集。画像マスク用エディタも提供。文字認識の対応言語・精度は実機で確認。

重複は同一デッキ内の問題形式・正規化した問題文・解答で候補提示し、初期動作はスキップ。更新／別ノート追加は明示操作のみ。更新時に学習の意味が変わるならFSRS履歴維持／初期化を確認する。

インポート時には、ファイルの取り込み失敗、パース失敗、入力未完備、画像保存失敗などを行単位で示す。成功件数・スキップ件数・エラー件数を表示。永続化は整合性を保ち、画像ファイルだけが残る状態も清掃・復旧可能にする。

## 8. 通知（今回確定したB方式）

### 利用者向け仕様

- 「復習が必要な日だけ通知」。新規未学習カードだけでは通知しない。
- 通知を利用者が設定画面でオンにしたときに通知権限を要求。拒否時は設定アプリへの案内を表示する。
- 通知時刻は初期20:00。原則1日最大1通。
- 通知本文は「今日の復習があります」等の固定文を基本とする。日々変化する枚数を予約済み通知へ埋め込むことはしない。
- タップ時はホームへ遷移し、復習開始アクションを表示する。

### 実装アルゴリズム（通知計画 `NotificationPlanner`）

- 現在時刻より後の通知時刻を、今後30日分計算する。
- 各候補時刻 `T` に対し、停止していない既学習Cardのうち、`dueDate <= T` で、かつ現在未完了のものがあるなら、その日を通知対象とする。新規Cardは除く。期限超過のCardは以降の日も対象になり得る。
- 同日に学習が完了したら、未配信通知を削除して再計画する。
- 予約は`UNCalendarNotificationTrigger(repeats: false)`による日付指定の単発通知。`review-YYYY-MM-DD`のような決定的識別子で重複登録を防ぐ。
- 前回登録済みの本アプリのレビュー通知と新しい計画との差分を算出し、不要な予約を削除・必要な予約を追加する。学習評価確定／Undo／Card追加・編集・削除／通知設定変更／アプリのforeground復帰時に再計画する。
- 手動でiPhoneの時刻・タイムゾーンが変わった場合も、次回アプリ起動／foregroundで再計画する。
- 通知済みのものは追加でその日に再通知しない。必要なら配信済み通知の掃除をする。
- ユーザーが30日を超えてアプリを起動しない場合、将来の通知補充は保証しない。iOS自体も配信時刻を保証しない。バックグラウンド常時実行は行わない。
- 20:00より後に期限到来するカードは当日の20:00通知対象に含めず、翌日以降に期限超過が続く場合に通知する。
- 学習日切替4:00は「1日の目標・新規上限・集計」に適用する。通知対象判定は通知時刻に実際にdueに達しているかで決める。

### 通知受け入れテスト

| ケース | 期待する動作 |
|---|---|
| 復習Cardが0枚、新規Cardのみ | 通知を予約しない |
| 明日11時に1枚期限到来、明日20時通知設定 | 明日20時を予約 |
| 明日21時に1枚期限到来、明日20時通知設定 | 明日20時は予約せず、翌日20時を予約 |
| 当日18時に復習を全件完了 | 同日20時の未配信通知を取り消す |
| 期限超過Cardを3日間放置 | 予約可能期間では各日20時に通知 |
| 通知オフ／通知権限拒否 | 通知を予約しない・設定案内を表示 |
| 評価Undo、Card一時停止・復帰 | 通知計画を再計算 |
| アプリを長期間開かない | 事前予約範囲外への配信を約束しない |

## 9. 触覚・アニメーション

- `HapticsService`をUIから分離する。設定：off / standard / rich。
- 通常のタップ・カードめくりはSwiftUIのsensoryFeedbackまたはUIKit標準フィードバック。
- 完了時など特別な場面だけCore Hapticsのカスタムパターンを使用。ハードウェア対応チェックとフォールバックを実装。
- 標準コンポーネントの触覚と二重発火しないようにする。
- アニメーションはカードめくり、回答確定、目標達成に絞る。Dynamic Type、VoiceOver、Reduce Motion対応を優先する。
- 学習・入力の成功を触覚だけで伝えない（視覚・読み上げでも区別できる）。

## 10. データ設計（論理モデル）

SwiftDataの`@Model`を利用。ただし循環リレーションや削除ルールの実装しやすさを優先し、まず次の論理契約を満たす。

| Entity | 主なフィールド |
|---|---|
| Deck | id(UUID), name, parentID?, sortOrder, createdAt, updatedAt |
| Tag | id(UUID), name, normalizedName |
| Note | id(UUID), deckID, type, contentPayload(versioned Codable), tagIDs, defaultResponseMode, createdAt, updatedAt |
| Card | id(UUID), noteID, variantKey, fsrsPayload(versioned Codable), dueDate, isSuspended, createdAt, updatedAt |
| ReviewLog | id(UUID), cardID, reviewedAt, grade, responseMode, durationMs, fsrsBefore, fsrsAfter, algorithmVersion |
| MediaAsset | id(UUID), relativePath, mediaType, width?, height?, sha256?, createdAt |
| ImportBatch | id(UUID), sourceType, createdAt, status, counts, errorSummary |
| SessionDraft | id(UUID), cardID?, answerMode, typedDraft?, currentScope, updatedAt |
| AppSettings | desiredRetention, dailyNewLimit, dailyGoal?, dayStartHour, notificationEnabled, notificationHour, notificationMinute, hapticsMode, siblingBuryEnabled, queueOrder |

- `contentPayload`は種別ごとに型付きCodableスキーマを用意し、将来のマイグレーションに備え`schemaVersion`を持たせる。
- CardのvariantKeyは `basic:front` / `basic:reverse` / `cloze:<stableID>` / `image:<maskID>`のような安定キーを使用。
- 画像はApplication Support配下の管理領域に保存し、SwiftData側はファイル参照を持つ。バックアップ・復元時は相対パスを再構築。
- 設定はUserDefaults（`@AppStorage`など）でよいが、バックアップ対象として明示的にシリアライズする。
- SwiftDataのtransaction/save/rollbackを適切に使用し、レビュー評価とログ追記に不整合を起こさない。

## 11. バックアップ／復元

- 独自拡張子`.studybackup`、実体はZIP（`manifest.json`、`data.json`、`media/`を含む）。
- manifestにschemaVersion、作成日時、アプリバージョン、チェックサムを含める。
- デッキ階層、ノート、カード、FSRS全状態、レビュー全履歴、画像、タグ、設定を保存。
- エクスポート成功後にiOS共有／ファイル書出しUIを表示。
- インポート時は先にZIP構造・サイズ・パス・ハッシュ・参照整合性を検証し、失敗時は元のデータを保持。
- 復元モードの初期実装は「既存データをすべて置換」。明示確認・保護された作業領域・検証済みデータへの切り替えを設ける。
- 外部から取り込むZIPはパストラバーサル、ZIP爆弾などを考慮した安全な展開処理にする。

## 12. 非機能要件

- 機内モードで登録・学習・画像表示・OCR・バックアップ等の基本機能が使えること。
- 起動後、データが存在してもホーム操作まで不必要なブロッキングが発生しないこと。
- 1,000ノート、3,000カード、10,000レビュー履歴を対象に最低限の動作試験を行う（性能目標は実機計測後に設定）。
- データ保存失敗を黙って無視しない。エラーUIと再試行手段を用意する。
- 通知権限、カメラ、写真へのアクセスは使用時に要求。不要な権限を求めない。
- 個人情報や登録内容を外部送信しない。アナリティクスSDKも初期実装には含めない。
- アプリ終了・OSによる終了・機種の時間帯変更・日跨ぎ・権限拒否の試験を実施する。

## 15. 最低限の自動テスト一覧

1. 新規Cardを`good`で回答するとFSRS状態・dueDate・ReviewLogが一貫して保存される。
2. `again`での短期復習、および回答時間経過後の再学習が意図した順で出題される。
3. 同一Cardに再回答する際、実際のレビュー日時がFSRSに渡る。
4. 直前の評価UndoでCard状態と履歴が元に戻り、再回答できる。
5. mental/typing切替でもCard IDとFSRS履歴が変わらない。
6. Clozeの穴を3つ作ると3Cardが生成され、同じvariantKeyで再生成してもIDが変わらない。
7. 画像マスクの位置が画面サイズ変更後も一致する。
8. CSVのカンマ・改行・クォートのあるフィールドを正しく処理する。
9. 重複Cardの取り込みで、既存のReviewLogを誤って消さない。
10. 学習目標20枚に達しても、残りの復習を続けられる。
11. 期限超過の復習Cardが翌日以降にも残る。
12. 通知対象0の日には通知を作らない。全件復習後は未配信通知を取り消す。
13. 新規カードのみの日には通知しない。
14. 学習日切替の午前4時直前・直後で日次新規上限と目標が正しく切り替わる。
15. バックアップ→アプリデータ初期化→復元でUUID、学習履歴、画像参照、FSRS状態が一致する。
16. 破損・悪意あるバックアップは拒否し、既存データを保持する。

### ホームの学習対象とセッション（Issue #28）

ホームの次回学習フィルターはExtraPreferencesの任意homeScopeとして保存する。既存バックアップの形式・SwiftDataスキーマは変更せず、値がない旧データは全デッキ・タグなし。シート内の変更・リセットは一時状態で、適用時のみ保存、キャンセルでは破棄する。保存失敗時は適用済み条件を変更しない。削除済み参照は読み込み時に除去する。

SessionScopeは開始時にだけ設定する実行中セッションの条件。ホームの適用で回答下書き・Undo・出題対象を変更しない。デッキは子孫込み、複数タグはAND。復習待ち・新規枚数は選択条件内、今日のユニーク学習枚数・回答回数・新規枠の消費は全デッキ共通。

### 復習優先ホーム（Issue #29）

上からナビゲーション「ホーム」＋カード追加、1行の学習対象、復習枚数と主CTA、続きから再開、ほかの学習、全デッキ共通の今日の学習を配置する。復習CTAを最も強いインディゴのボタンにし、通常文字サイズではスクロールせず開始できる配置を優先する。新規と混合は縦の標準リスト行。詳細統計は記録タブに置く。

モード表示は「復習する」「新しく覚える」「復習＋新規」。常時説明は順に「復習のタイミングになったカードを学習します」「まだ学んでいないカードを学習します」「復習と新しいカードを組み合わせて学習します」。mixedの保存値・3:1キューは維持。補足は標準ヘルプシートで確認できる。dueCount/newCount/goalProgress/start-review/start-new/start-mixedは維持し、studyDeckPickerはフィルターシートに移動。

### ホームの状態制御（Issue #30）

復習0件・新規0件・混合0件では各開始操作を無効化する。開始時にも実際のキューを検証し、空なら既存セッションを置換しない。未登録はカード追加へ誘導。フィルター内0件と他の対象に残るカード、新規上限・未学習なし・兄弟カード待機を区別する。新規枠の案内は設定した学習日開始時刻を表示する。短期復習の将来到来は完了とせず待機表示する。目標達成で学習操作を制限しない。

中断再開は元のモード・スコープ・下書き・Undoを維持し、カードのない待機中セッションを含め、新しいモードへ切り替える際は破棄確認を出す。読み込み失敗は0件表示に置換せずエラーと再試行を表示し開始を抑止する。

### ホームの更新と品質（Issue #31）

起動・データ変更・学習終了・フィルター適用・復元はフル読み込みで整合させる。ホーム復帰と15秒周期はHomeSnapshotでカード状態と当日の履歴だけを集計し、全ノートの表示生成・全履歴統計・保存は行わない。期限到来・学習日境界・時間帯変更を同一時刻のスナップショットで反映する。値が変化した部分だけ公開し、読取失敗は最後の正常値を保持してエラー表示する。

通知はデータ変更とアクティブ復帰、日付/時間帯・全体の復習枚数変化で差分再調整する。単なる周期更新は通知を再予約しない。中断の時間計測はシーンの実際のアクティブ状態変化時のみ保存する。記録タブを開く際はホーム集計と詳細統計を更新する。ホームの復習待ちは絞り込み後、今日の学習は全デッキのユニーク枚数、回答回数は全デッキの延べ回数。

通常文字サイズのコンパクト画面でも復習を開始できる配置とし、最大Dynamic Typeは固定高さを避けてスクロール可能にする。操作名・件数・対象・目標をVoiceOverに渡し、文字とアイコンの意味が重複しないようにする。ホームには独自のアニメーションを導入しない。実機・VoiceOver音声・OSのReduce Motionの受け入れは#3と連携して別に記録する。
