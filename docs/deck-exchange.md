# デッキファイル交換（Issue #16）

書き出しはライブラリ → デッキ管理 → デッキファイルを書き出す。取り込みはライブラリ → インポート、またはデッキ管理 → ファイルを取り込む。デッキのコンテキストメニューから開くと、そのデッキを初期取込先にする。送信側はデッキを選び、内容を確認してからFilesまたは標準Share Sheetへ渡す。受信側は.studydeckを選択し、階層・件数・ノート内容・重複数・取込先名称を確認して、最後に確定する。プレビューの取消は保存しない。

## 形式と個人データ

studydeck manifestのformatは`studydeck`、schemaVersionは1。無圧縮ZIPにmanifest.json、deck.json、media/UUID.extを格納する。deck.jsonのトップレベルはschemaVersion/rootID/decks/notes/mediaのみ。バックアップのdata.jsonや学習履歴は格納しない。将来の非互換変更ではバージョンを上げ、未対応版は既存データを変更せず拒否する。

選択したデッキを共有階層の最上位にし、全子孫・全ノートと使用するタグ名・画像・音声だけを含む。ノートの問題、答え、解説、ヒント、逆方向、画像遮蔽、回答方法、TTS用の英文は内容として残す。カードUUID・FSRS・ReviewLog・停止状態・作成/回答日時・デッキの制限・保持率・通知・自動音声設定・下書き・取込履歴・未参照メディアは含めない。ノートの自動音声overrideも除外し、受信側で継承する。

書出前のプレビューに階層、ノート数、生成カード数、メディア数を表示し、ノート本文は100件ずつ確認できる。ファイルにはノートの全本文やタグが入るため、プレビューで共有したい内容か確認する。

## 取込

追加ノートは新しいUUIDで作成し、全カードを未学習・停止なしで開始する。既存ノートの更新は、統合時に差分を確認して対象ごとに明示同意した場合に限る。既定の新規デッキ追加では、同名の最上位デッキは「名前（取込 2）」などへ自動で変更し、子孫階層は新規ルート内に保持する。既存ノートとパッケージ内の本文・形式・画像/音声のハッシュが一致するものを重複として表示する。タグと回答方法の違いは重複判定に含めない。既定はスキップで、切り替えると別ノートとして追加する。重複判定・取込先名称は確定時に再確認する。全件スキップならデッキやファイルを作成しない。

## 検証・原子性

合計200MB・1万ZIPエントリー・各50MB、最大1万デッキ・10万ノート・30万生成カード。画像/音声には既存の20MB・画素・時間・全体デコード制約を適用する。ZIPの中央/ローカル記録、サイズ、CRC、パス、シンボリックリンク、重複ファイル、ファイル集合、SHA256、参照、単一ルート、階層サイクル、画像/音声の役割を検証する。暗号化・ZIP64・圧縮・再圧縮は未対応。studybackupは受け付けない。

ファイル選択・検証は端末内の背景タスクで行う。検証済み値は専用の非公開initializerでのみ生成でき、確定時は音声を再デコードしない。原子的な1回のDB保存にDeck/Note/Card/Tag/MediaAssetをまとめ、失敗時はロールバックして新規ファイルを除去する。共有ファイル用の一時領域は画面を閉じるかプレビューを変えると削除する。取消・画面離脱は背景処理をキャンセルする。

## Issue #106：取込先選択（第1段階）

.studydeckでは既定の新規ルート追加に加え、既存デッキの下への追加、選択した既存デッキへの統合を選べる。統合ではルートを選択先に対応付け、子孫は親と名前が一致する既存デッキが1件だけで、受信側の同名兄弟も1件だけなら再利用する。候補が複数ある場合は別名新規作成し、既存デッキを移動・削除しない。変更前後のフルパス、追加／再利用デッキ数、追加ノート数をプレビューに表示する。

確定時に階層マッピングと重複集合を再計算し、確認済みプレビューと異なる場合は保存を拒否して再プレビューする。全件重複スキップでは確定できず、デッキやメディアも作らない。保存は従来どおり1回のトランザクションで行い、既存カードID・FSRS・履歴・セッションを変更しない。新規デッキ／ノート／カードは新規UUIDとする。APKGは従来の新規ルート追加を維持する。

### 既存ノートの更新（第2段階）

「既存デッキに統合」で、受信ノートUUIDが既存UUIDと一意に一致し、対応先デッキ・形式・variantKey集合・カード数・identityKeyを維持できる場合に限り、ノートごとの更新を選択できる。本文一致・類似だけでは同一性を推測しない。通常の別端末からの追加ではUUIDを新規生成するため、元ファイルのUUIDとの対応は残らず更新候補にはならない。安全に特定できない場合はスキップ／別ノート追加を利用する。

既定はスキップ。同一UUIDの変更ノートも未選択なら重複方針に従う。差分には問題・解答・ヒント・解説・タグ・画像／音声・回答方法・読み上げ・レイアウトと、変更しない項目、カード数・生成／削除への影響を表示する。各ノートの確認欄で履歴方針に同意し、最後に取込全体を確認する。

出題・解答・出題メディア・回答方法などが厳密に同一で、ヒント・解説・タグ・レイアウトだけが異なる更新はFSRS-6・due・ReviewLog・停止状態とノート／カードUUIDを保持する。一問一答・記述式の出題／解答などが変わる場合は、未学習リセットへの同意を必須とし、FSRS状態・due・カード更新日時のみ初期化する。過去のReviewLog・UUID・停止状態は維持する。形式／カード構成の変更、穴埋め・画像マスクの出題変更、学習中／Undo対象のノートは更新を禁止する。

確認済み候補の本文・タグ・カード状態とrepositoryの変更世代を再検証する。取込先変更・保存失敗・再プレビューで同意を破棄し、再確認を要求する。同じ内容の添付メディアは既存UUIDを再利用する。変更メディア・タグ・ノート・FSRSの保存は既存の単一トランザクションを使い、失敗時にロールバックして新規メディアを除去する。UIからの確定前は既存の完全バックアップ復元ポイントを必須とする。

v1交換形式、SwiftDataスキーマ、完全バックアップの仕様は変更しない。共有元の学習履歴を取り込む機能ではない。

2026-10-14にDebugビルド、関連結合テスト7件、iPhone 15 Pro / iOS 26.5 Simulatorでの代表UI操作1件が成功。UIは隔離ストアの検証済みファイルfixtureから、差分表示・同意なしの確定禁止・取消・履歴保持更新・解答／画像変更のリセット・結果表示を確認した。実機とFiles選択UIの再確認は未実施。差分画像：[履歴保持](assets/issue106/preserve-diff.png)／[未学習リセット](assets/issue106/reset-diff.png)。

## 共通のインポート入口（#108）

「ファイルを選択」でCSV / TSV / TXT / 画像ZIP / .studydeck / .apkgを選ぶ。ZIPは既存のサイズ・パス・CRC検証を通して内容を判定し、デッキのmanifest/deck.json、Ankiのcollection、画像ZIPのcards.csv/cards.tsvを区別する。.zipに改名した対応パッケージも内部構造で認識する。複数形式の構造が混在する、拡張子と内容が違う、バージョンやチェックサムが不正な場合は別パーサーへフォールバックせず拒否する。完全バックアップ（.studybackup、またはmanifest.json + data.jsonを含むZIP）は設定 → バックアップ・復元へ案内し、取り込まない。

形式別の列編集・行除外・メディア・階層・Ankiの未対応理由を維持し、保存は既存のrepositoryへ渡す。すべてのプレビューに同じ下部固定の「取り込みを確定」を置き、0件・処理中は無効にする。ファイル変更は読込・検証成功後に既存の入力/プレビューの破棄を確認する。取消や読込失敗では元の入力を保つ。読込中は取消可能、保存中は二重実行と画面破棄を禁止する。保存後は既存の共通完了ヘッダーと形式別の実保存結果・保存先・閲覧導線へ接続する。

取込ファイルの検証はutilityタスクで行い、SwiftDataへの保存は既存MainActor制約を維持する。大量取込の保存・リロード中の応答性改善は#159/#173で追跡する。
