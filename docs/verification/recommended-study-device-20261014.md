# おすすめ学習・FSRS優先順位・中断再開の実機検証

2026-10-14。対象はPR [#195](https://github.com/shougayaki-1/anki-iOS/pull/195)・[#197](https://github.com/shougayaki-1/anki-iOS/pull/197)を含む取得時のmain `26dd6af999957744d97c1a59fd026486d3a227b8`。AGENTS.md、docs/requirements.mdのおすすめ学習・中断再開・忘却リスク順、両PRの説明を確認。実機で機能を確認し、再開時の重複ノート取得を修正した。操作が完了しなくなる状態・学習データの不整合は確認されなかったが、短いMain Thread停止は検出された。

## 環境と隔離

- iPhone 15 Pro / iOS 27.0.1 (24A446)、Xcode 27.0 (27A266a)、Debug / -Onone、ネットワーク接続。今回の数値は実機。シミュレーターによる代替検証ではない。
- 検証用コピーのBundle IDは `dev.shoug.AnkiIOS.RecommendationAudit20261014`。Widget・テストターゲットも別IDにし、App Group文字列も変更、アプリ/Widgetのentitlementsは空にした。本番Bundle IDや共有コンテナーをインストール・読取・上書きの対象にしていない。
- UIは `-study-test-store <UUID>` による専用SQLiteストア・専用メディア領域。再起動時だけ同じUUIDを使用。APIテストはメモリストアまたはUUID別の一時ディスクストア。本番データの初期化・移行・復元・一括更新は実施しない。
- Context7からApple SwiftDataのModelConfiguration（明示URL/メモリストア）の最新ドキュメントを取得してから修正した。
- 隔離構成のため、Widget・App Group共有・本番コンテナーでの動作は未検証。

## 機能結果

「実機API」は端末上の単体・結合テスト、「実機UI」はXCTestによる端末画面の操作と画像確認。成功はその範囲内での判定。

| 項目 | 判定 | 根拠・範囲 |
| --- | --- | --- |
| 復習待ち枚数と対象 | 成功 | UIで1/200/3,000枚を表示して開始。APIで3,000枚を集計し、デッキ/タグ/回答形式/休止などの除外後に順位付けされることを確認 |
| 回答上限は回答回数 | 成功 | APIで同じカードをAgainで2回答、上限2の残り0、履歴2件を確認。Undoで1回答へ戻る。UIでAgain→Undo→残り20問へ戻る |
| Againの再出題・進捗 | 成功 | APIの時計を次回期限へ進め、同じカードIDに再回答。UIでAgain/Undo後も中断・再開できる |
| 待ち枚数が上限超過なら忘却リスク順 | 成功 | APIで21枚/上限20の保存ポリシーがforgettingRisk。異なるFSRS状態の実際の出題順は想起確率の低い順。短期優先・予測失敗fallbackも確認 |
| 通常「復習する」は従来順 | 成功 | APIでmanual startがtraditional。期限順と忘却リスク順で実際のカード順が異なるfixtureを確認 |
| 推定時間・理由と開始ポリシー | 成功 | UIで24秒中央値、1枚→約1分/期限順、200枚→約8分/忘却リスク理由。APIで中央値・対象条件・不足値・日境界/タイムゾーンのキャッシュ、開始時の設定再確認 |
| デッキ休止 | 成功 | 実機APIで親子デッキの枚数/キュー除外、再開、下書き・Undo・FSRS保持、保存失敗rollback。休止設定の実機UI操作は未検証 |
| 学習対象の変更 | 成功 | 実機UIで空デッキの選択を取消/適用、0枚表示、再起動後の保持、元のセッション/下書きの再開、対象のリセット |
| 既存セッションを置き換えない | 成功 | 中断中はおすすめCTAを出さず再開CTA。APIでstartRecommendedを既存セッションに再実行してもカード/入力/履歴/Undoを保持 |
| 未回答入力→中断→ホーム再開 | 成功 | 1枚と3,000枚で入力文字列・質問を照合。元のカードへ戻り、回答・Undo可能 |
| アプリ再起動後の再開 | 成功 | 中断→terminate→launch→ホームから再開し、同じ質問・未回答入力を確認。ディスクAPIでもID/FSRS/期限/履歴/Undoを保持 |

Undoは従来仕様として評価を取り消し、入力下書きと回答表示をリセットする。Undo後は新たに「Restart draft」を入力してから中断・再起動し、その入力の保持を確認した。未回答入力の消失とは区別する。アプリ再起動はプロセス再起動であり、iPhone本体の再起動ではない。

## 性能と修正

### API測定（取得時main、実機、単回）

3,000カード/10,000履歴。homeSnapshotはメモリストアの集計で描画を含まない。復習開始/Good評価/Undoはwarm decode cacheのRepository API。ホームwarmは5回平均。

| 項目 | 時間 |
| --- | ---: |
| ホームsnapshot初回 / warm | 57.32 / 54.01ms |
| 従来順の開始 / Good / Undo | 116.12 / 124.75 / 3.05ms |
| 忘却リスク順の開始 / Good / Undo | 137.94 / 143.33 / 6.27ms |

warmホーム更新で追加の回答時間fetch・全履歴fetch・FSRS decodeなし。両順位の評価でFSRS decodeは1、全履歴fetchは0。

PR #195の既存値はiPhone 17 Pro / iOS 26.5 **シミュレーター**、従来順119.46/132.06/5.47ms、忘却リスク134.15/148.20/9.13ms。PR #197の47.4/43.9msもシミュレーター。今回の実機値と環境が異なるため改善率/退行率を算出しない。

### 実機UIとMain Thread

UI fixtureは専用ディスクストアの3,000 basicノート/カード、期限到来済みreview、推定時間用の履歴5件。上のAPI fixtureとは異なる。初回fixture生成を除き、起動・ホーム更新（記録タブ往復）・おすすめ開始・Again確定・Undo・中断再開を測定。XCTestのtap、snapshot、idle待機を含む壁時計値は処理時間やMainActor停止時間と同一視しない。

修正前の単回UI壁時計：起動ホーム3,335.72ms、更新2,817.60ms、開始1,758.34ms、Again1,680.14ms、Undo2,505.77ms、中断＋再開4,134.82ms。

Time Profiler + os_signpostは専用Bundle IDと実行パスでPIDを照合して接続。修正前16.09秒の採取で250ms閾値のpotential hangを2件検出した。

- 318.33ms（開始0.6007秒）：UIKitのkeyboard focus/input view準備経路を含む。対象操作のRepository/Store signpostとは重ならず、今回の修正対象から外した。
- 301.16ms（開始5.6685秒）：再開時のStore.refreshStudy 209.80ms（開始5.6978秒）と重なり、SwiftUI/AttributeGraph更新とノート投影を含む。queueNotesが1操作内で3回実行されていた。

開始/評価/Undoで既に利用している `withStudyQueueReuse` をpause/resumeにも適用した。読み取ったノート投影を同じ操作内だけで共有し、既存のトランザクション開始/rollback時の無効化、操作終了時の破棄を維持する。永続スキーマ・FSRS・回答順序・Undo仕様は変更しない。回帰テストでノート取得をpause/resume各1回、下書き保持、両操作の保存失敗時のID/FSRS/履歴保全、デッキ休止変更後の再判定を検証する。

修正後のUI壁時計（同じ条件の単回）：起動ホーム3,530.72ms、更新2,807.24ms、開始1,754.76ms、Again1,651.19ms、Undo2,526.51ms、中断＋再開3,887.15ms。自動操作の待機を含むため、この差からUI改善率は断定しない。

修正後37.83秒のtraceでは中断/再開のrefreshStudyが123.89/122.60ms、各queueNotes 1回。修正前の212.78/209.80ms・各3回から重複取得が減った。AgainのStore.gradeは174.51ms、Store.undoは129.80ms。中断/再開の区間に250ms以上のpotential hangは検出されなかった。

**残存問題（失敗）**：おすすめ開始では333.33msのpotential hangが1件（開始20.3073秒）残る。startRecommendedの再検証refreshHome 71.08ms、Store.start 153.34msとSwiftUI更新を含む区間で、Main Threadサンプルにもこの経路を確認。再開用キャッシュの修正対象外であり、停止ゼロの基準（今回のInstruments閾値250ms）は満たさない。修正前traceはこの開始区間を採取できていないため、修正による新たな退行とは判定しない。安全のための開始前再検証を省略する変更は加えず、この停止とキーボード準備の停止は別途調査対象として残す。操作は完了し、カード/入力/回答履歴の不整合は確認されなかった。
