# #156 表示画像の軽量化

ライブラリ詳細・弱点練習・学習・画像ZIPの表示対象プレビューを、Image I/Oによる表示用縮小画像に変更した。専用actorでデコードを直列化し、Viewのbodyと評価可否判定から原画像デコードを除いた。編集・OCR・保存・バックアップは原本を使う。

ファイルのキーはストア世代UUID、URL、最新の更新日時・サイズ、256px単位の表示サイズ（最大3072px）。URLのメタデータキャッシュを毎回破棄する。Data入力はSHA256とサイズで識別する。EXIF変換済みのビットマップを保持し、LRUの実ビットマップ費用は24MiB、件数は64件まで。メモリ警告と復元でキャッシュを消去し、復元時は世代UUIDも変更する。画面外ではViewが保持する画像を解放する。可視View・デコード中の画像と入力Dataはキャッシュ容量とは別であり、これはプロセス全体のRAM上限ではない。

task(id:)のキャンセルとカード/世代/表示サイズ判定で旧結果の表示を防ぐ。画像のある学習カードでは正常な画像の読み込み完了後に評価を許可する。破損・欠落時はエラーを表示する。

## 検証

- iPhone17Pro / iOS26.5 Simulator、Debugビルド。
- メディア関連6件：EXIF8方向、透過、キャッシュ再利用/上限、更新/削除/世代/キャンセル/破損、原本保持、マスクとIDのディスク再読込、OCR・バックアップ。更新/削除テストの失敗を修正し、その1件を再実行して成功。
- UI1件：非同期読み込み後のマスク非表示/回答表示、評価、Undoによる再表示に成功。
- 4000×3000画像20枚の逐次デコード：従来相当のフル画像描画298.61ms、表示用1536pxデコード222.88ms。1枚のビットマップ24,000,000B→1,769,472B、キャッシュ24,772,608B。合成JPEG・シミュレーターでの計測であり、実機RAMや画面ハングの測定ではない。

実機が未接続のため、20〜100枚の実写真・細字図表・マスクの連続閲覧/再訪、ピーク/滞留RAM、ハング、見た目の品質は未確認。Issueの実機受入条件は未完了。PR #149とのLibraryView変更箇所の統合確認も必要。
