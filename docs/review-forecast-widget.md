# これからの復習 Widget (#234)

Medium専用。7本の棒に日付・曜日・枚数を対応させ、最多日と「そろそろ復習したい1枚」を表示する。0件は基線と数字0で表し、全日0件なら予定なしと表示する。棒は平方根スケール（正の値には最小高さ）で、極端な集中日があっても少ない日の存在を読めるようにする。高さの比較は線形ではないため、正確な数量は各棒の数字を読む。最多は共通PrimaryAction色の濃さと見出しで示す。問題は1行まで、答えは共有しない。画像はアプリ確認へ誘導する。

## 保存済み期限と期限超過

現在のホーム学習範囲（デッキの子孫・タグのAND条件）を既存scopedQueueCardsで解決する。停止・有効休止・削除済み・現在の当日非表示カード、新規カードを除外する。兄弟抑制は一時的な出題可否なので、グラフの保存済み期限からは除外しない。同一UUIDは1回だけ数える。

既存StudyDayの設定値（既定4:00）と現在のCalendar／タイムゾーンで今日を含む7学習日を作り、ReviewForecast.scheduledIndexを再利用してdueDateを区分する。ただし**今日の学習日開始より前**の期限はグラフへ混ぜず「期限超過」に別計上する。今日の開始以上・明日の開始未満は今日の棒で、今日すでに時刻が過ぎた期限もここに含む。明日以降は各区間[start, end)に数える。7日目終了以降は期間外。

ReviewForecast.scheduledの「期限超過も今日にまとめる」定義から期限超過を明示的に分離したもの。projectedAnswersや毎日Good回答のシミュレーションは実行・表示しない。グラフは現時点の保存済み期限であり、未来の確定学習量や回答回数ではない。「保存済み期限・学習で予定は変わります」と常時表示する。一時非表示中の予定は再表示後に再集計される。

## 1枚の選定と正式キュー

既存ReviewQueueBuilderのreviewモード／forgettingRisk順をそのまま使う。現在のスコープ内、未停止・未休止・非表示でない、due <= nowのカードだけが候補。兄弟埋没も正式キューと同じ。新規カードへのフォールバックや未期限カードの先取りはしない。

1. 学習中・再学習中の短期ステップを期限→UUID順で優先。
2. 長期reviewは既存ReviewSchedulerで現在のRetrievabilityを一度ずつ計算し、低い推定値から並べる。同値は期限→UUID順。
3. canRankReviewを満たさない状態、欠損・範囲外・非有限の推定値は、既存ランキング同様、期限→UUID順の元の位置を維持する。有効な推定値を持つカードだけを残りの位置で並べ替える。

有効な個人最適化パラメータを使用し、未最適化なら既定FSRS-6を使う。Retrievabilityは過去の評価と経過時間に基づくモデルの想起可能性の推定であり、実測正答率や記憶の有無の判定ではない。固定閾値を設けず、「忘れた」と断定しない。短期ステップや推定不能カードが先頭になる場合も正式キューの安全な優先順位を尊重する。乱数を使わないため、同じ入力なら同じ1枚になる。

## 表示・導線・共有

#230のDailyWidgetCard、問題文の短縮・画像案内をwidgetDisplayCardに共通化し、カード指定Deep Linkを再利用する。アプリで対象の存在・スコープ・休止・停止・期限を再検証する。対象外なら既存の案内からホームへ戻り、別カードを代わりに提示しない。既存セッションとUndoを破棄しない。開始時はpreferredCardIDを固定復習セットの上限適用前に優先配置する既存経路。正式評価はアプリ内だけ。候補なしは「今の復習はひと区切り」からホームへ。グラフは既存の記録／分析タブへ進む（そこから復習負荷予測・学習計画を開ける）。日別絞り込みは追加しない。

App Groupの既存progress-v1.jsonに任意のreviewForecastを追加。7日分の枚数・日付、期限超過数、問題のみの1枚を共有する。schemaVersionは1のまま、旧JSONはnilとして読める。ExtensionはSwiftData・FSRS・履歴を読まず、既存の生成時刻・タイムゾーン・有効期限も検証する。

## 更新・性能・データ保護

既存Publisherのキャッシュ・重複抑制・generationキャンセル・atomic書き込みを利用。保存済み期限の集計とランキングはutility Taskで実行し、FSRSの入力は既存キューキャッシュのData値のみ。履歴は既存の当日ログを使い、全履歴の新規取得はしない。候補ごとに1度だけFSRSを呼ぶ。表示カードの最小限の内容だけMainActorで取得する。

学習・Undo・設定／スコープ・編集／削除・休止・復元後は既存更新経路から再生成し、4種類のWidgetへreloadを要求する。OSが描画時刻を決めるため即時更新は保証しない。新しい期限到来・次の学習日開始・既存投影期限のうち最も早い時刻で予報とカードを失効させ、古い値を新しい予報として出さず「アプリを開いて更新」へ切り替える。タイムゾーン変更でも古い値を隠す。予報は当日限りで、翌日の7日分を根拠なく作り足さない。

計算・表示は読み取り専用。FSRSの状態、期限、ReviewLog、Streak、保存・再開、Undo、バックアップ仕様、Live Activityを変更しない。書き込みは共有表示ファイルだけ。投影失敗時はDBに触れず、旧ファイルは旧生成時刻と有効期限のまま残る。
