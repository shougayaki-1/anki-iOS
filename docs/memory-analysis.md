# 記憶の状態（Issue #101）

記録 → 現在の定着状況 → 記憶の状態を詳しく見る。記録タブのデッキ（子孫を含む）・全指定タグの条件を引き継ぐ。読み取り専用で、FSRS・予定・UUID・履歴・学習セッションは変更しない。

| 指標 | 対象・算出 | 表示・深掘り |
| --- | --- | --- |
| 安定度 | 現在の学習済み・非停止カードのStability。90%想起の時間尺度（日） | 中央値・最小/最大・0/1/7/30/90日の区間別枚数 |
| 難易度 | 同じ対象のDifficulty（FSRS正規化範囲1〜10） | 中央値・範囲・1/3/5/7/9/10の区間別枚数 |
| 想起確率 | 同じ対象を集計時刻・有効な個人最適化パラメータでFSRS-6計算 | 中央値・範囲・20%ごとの区間。確率の和は推定記憶済み枚数 |
| 実測保持率 | 7/30/90学習日（今日を含む）で、評価前snapshotがreviewのカード×学習日の最初の対象評価。日時、同時刻はsequence順。Again失敗、その他成功 | 成功/試行、成功・失敗グラフ、期間、対象カード。0試行は「—」、20未満は比較しない旨を表示 |

現在のカード指標には短期学習・再学習を含み、未学習・停止・削除カードは除外する。非有限・各モデル範囲外の値は除外する。数値は小数第1位、中央値は偶数個なら中央2値の平均。区間は下端を含み上端を除く（最終区間の上端のみ含む）。

実測は保存済みfsrsBeforeから評価前状態を読むため、学習/再学習の反復は分母に入らない。停止カードの過去試行は残る。削除済みの履歴は全体に残り、現在の所属で再分類できない履歴は絞り込み時に除外する。Undoで削除された履歴は再集計時に消える。現在のタグ・デッキで過去の履歴を分類する点は既存統計と同じ。削除カードの根拠IDは表示できるが、本文は復元できない。

目標は現在の設定（デッキ自身から祖先への最初の上書き、なければ全体設定）。複数の目標は全値を併記し平均しない。過去の設定値と同じとは保証せず、観測値との優劣は断定しない。

統計Actorの既存revision付き材料キャッシュを再利用し、カード・履歴モデルをMainActorに渡さない。現時点の分布と実測集計もActor上で行う。画面再訪・更新・データ変更・復元で再評価し、foreground復帰・学習日/タイムゾーン変更を検知する。画面の時刻進行だけで想起確率を常時再計算しない。区間選択と同じ数値のNavigationLinkを用意し、VoiceOverでもカード一覧へ進める。常時アニメーション・触覚は追加しない。

検証: StatisticsTests、専用Repository統合テスト、既存の削除履歴/デッキ階層テスト、3,000カード/10,000履歴の材料キャッシュ計測、代表的な画面導線のUIテスト。実機の手動確認は別途必要。

代表画面（分離テストストア・iPhone 17 Pro / iOS 26.5）: [概要](verification/issue101/summary.png)、[安定度分布](verification/issue101/distribution.png)、[区間の根拠カード](verification/issue101/evidence.png)、[実測0試行](verification/issue101/retention.png)。Fixtureは期限到来日時へ仮想時刻を進めるため、画像内の日付は検証実行日と異なる。

結果: 関連単体・統合・性能13件成功、UI導線1件成功。Debugビルド成功。3,000カード/10,000履歴ではcold 511〜524ms、同スコープ再訪24〜26ms（シミュレーター、Actor上での集計）。実機、グラフのドラッグ選択、VoiceOver手動操作、ダークモード/文字拡大は未確認。
