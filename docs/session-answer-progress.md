# 学習セッションの回答数・残り問題数（Issue #55 第1段階）

## 意図
学習画面で「今日の目標を達成しました」を見せるのではなく、**現在の学習セッションの終点**を提示する。FSRS-6の復習キューは短期再学習によって増減するため、キューのカード枚数を「残り問題数」として使用しない。

## UX
- ホームの「今回の回答数」から 10／20（初期値）／30／すべて（無制限）を選ぶ。毎回設定画面を通ることなく復習・新規・混合を従来どおり開始可能。
- 学習画面の固定ヘッダー：例「残り13問　今回 7 / 20問」と進捗バー。問題本文だけスクロール可能。
- 「すべて」の場合は「今回回答済み N問」と表示し、残り枚数や100%の進捗バーを偽らない。
- 学習画面の「今日の目標を達成しました」文言と日次ユニーク枚数による進捗表示を取り除く。日次目標はホームの進捗欄に残す。
- 20回目の回答確定でそのセッションの完了画面に移る。最終回答のUndoは完了確定前まで可能で、途中終了は「中断」と区別する。
- 対象カードが先に尽きたときは、既存の空状態判定（短期復習待ち、兄弟カード抑制、新規上限など）を優先し、回答済み数を保持する。

## カウント
- 回答確定 = Again/Hard/Good/Easyの評価ログを**保存できた1回**。同じカードの再学習であっても1回ずつ加算。
- Undoがログを削除したら1減算。ヒント表示、模範解答の表示、並び替え途中操作・正誤判定だけでは加算しない。
- Session開始時点の最大ReviewLog.sequenceをStudyOptionsのオプション情報に保存し、現在の最大シーケンスではなく**開始以降に残っているログ件数**を集計する。
- ユーザーがホームの回答数を変更しても、実行中セッションに保存した値は変更しない。
- アプリ再起動、バックグラウンド、中断／再開、完全バックアップ後に同じStudyOptionsペイロードから復元する。既存SwiftDataスキーマの変更はしない。
- アップデート前から進行中のセッションで開始時シーケンスが不明な場合は、残り問数を推測して表示しない。新規セッションから適用。

## 注意
今回のPRは #55 のうち **回答数と残り問題数の実装** に限定する。開始前の回答形式の一括指定（「カードに合わせる」等）や追加の学習開始導線は別PRとし、Issue #55はその受け入れが完了するまで残す。

### テスト
- 単体・結合：20回答で終了、日次目標との独立、Undo、当日中の次セッションを0から開始、再起動、無制限と途中設定変更。
- UI：新規学習初期表示「残り20問」→1回答「残り19問」→Undo「残り20問」、従来の日次目標の表示がないこと。
- 回帰：短期反復、ヒント・英文並び替え、バックアップ復元、デッキとタグのフィルター、最大Dynamic Type、iOS 17以降。

**CI・Xcodeビルド・シミュレーターでの実行結果はPR作成時点で未確認。** 実装の受け入れ前にMac上で検証すること。

## 開始前の回答形式（Issue #68）

ホームの「学習設定」で回答数と「カードに合わせる／頭の中／文字入力／並び替え」を保存する。通常は保存済み設定で1タップ開始できる。既定はカードに合わせる。設定は次のセッションだけに適用し、中断中の方式・入力下書き・Undoを変更しない。「もう1セット」も元のセッションの方式を引き継ぐ。セッション中の方式変更は現在のカードだけに適用する。

並び替え指定時は既存の英文並び替え判定を使い、表示される解答が対応する一問一答・記述式カードだけを出題する。非対応カードを他方式へ変換しない。ホーム件数も対応カードの件数になり、対象がない場合は理由と回答形式変更の案内を表示する。3学習モード、新規枠、兄弟抑制は通常のキュー規則を維持する。

設定と開始時スナップショットは既存のStudyOptions JSON内のOptional値として保存し、完全バックアップと復元で保持する。旧データの欠落値・未知の方式はカードに合わせる。SwiftDataモデル、カードの既定方式、UUID、FSRS、ReviewLogは変更しない。
