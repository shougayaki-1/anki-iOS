# 触覚フィードバック

Issue #89のP1監査・誤発火修正。触覚は操作結果の補助であり、表示・入力・保存・読み上げの代わりにはしない。

## 設定と発火条件

- オフ: アプリ独自のUIKit / Core Haptics / SwiftUI sensoryFeedbackを抑止する。OS標準コントロールの触覚は対象外。
- 標準: 下表のプリセット。4評価の強さは共通で、Againを罰として扱わない。
- 豊か: 標準と同じ。設定したセッション回答上限に初めて到達した評価だけ、対応機器で3連のカスタムパターン。日次目標とは別。無制限、手動終了、候補が尽きただけの場合は完了触覚を鳴らさない。
- UIKit / Core Hapticsはアプリactive時のみ、並び替えのSwiftUI触覚はscene active時のみ。Core Haptics非対応・エンジン失敗時は標準successにフォールバック。触覚非対応機器でも操作は継続できる。

| イベント | 発火契機 | 標準の触覚 / 回数 |
| --- | --- | --- |
| スワイプ準備 | 評価・答え表示の閾値通過 | selection / 閾値通過ごと（既存の再進入抑制） |
| 答え表示 | 下書き保存・画面反映後、未表示から表示へ変化 | soft / 1回。スワイプ準備済みなら追加しない |
| Again / Hard / Good / Easy | 評価保存・画面反映成功 | light / 1回。スワイプ準備済みなら追加しない |
| セッション上限到達 | 未完了から上限到達への評価 | success / 1回。通常評価の触覚と排他 |
| 達成画面表示 | 日次目標・連続学習・初回学習・習熟達成の演出 | なし。上限到達時の触覚を再発火しない。Reduce Motion時も同じ |
| Undo | Undo保存・画面反映成功 | selection / 1回 |
| 語句追加・取消 | 下書き保存・画面反映成功、状態変化あり | selection / 1回 |
| ドラッグ持ち上げ | 選択済み語句のドラッグ開始 | light（0.45） / 1回 |
| 挿入先変更 | ドラッグ中の挿入先変更 | selection / 最短100ms間隔。初回進入はなし |
| 移動ドロップ | 位置変更の保存・画面反映成功 | light（0.55） / 1回 |
| VoiceOver移動 | 位置変更の保存・画面反映成功 | selection / 1回。成功時だけ移動結果を読み上げ |
| 並び替え判定 | 判定保存・画面反映成功、試行回数増加 | 正解success / 不正解error / 1回。答え表示と排他 |
| ノート保存 | 編集・一括登録・デッキ操作等の明示的保存成功 | success / 1回 |
| インポート完了 | 完全成功の結果表示 | success / 1回。部分成功では鳴らさない |
| バックアップ・復元完了 | 成功結果の表示 | success / 1回 |
| Widget手動更新要求 | 要求受付 | selection / 1回。Widget表示更新完了を保証しない |

並び替えは`StudyStore.ordering`の戻り値を成功した状態変化の確認に使う。保存失敗、無効・同位置移動、空リセットでは確定触覚を出さない。失敗したVoiceOver移動も成功を読み上げない。ドラッグ取消・同位置ドロップでは確定触覚なし（持ち上げ・挿入先変更の触覚は取消前に発生し得る）。再描画・中断再開だけではパルスを更新しない。保存成功後に画面取得が失敗した場合も確定触覚なし。

## 追加対象と未確認

既存の保存・取込・バックアップ・Widget要求の触覚を維持。タブ切替、スクロール、通常の画面遷移、ライブラリの複数選択・削除、デッキ休止等への新しい触覚追加は今回の対象外。実機の感触を確認する前に発火数を増やさない。Reduce Motionは既存の移動アニメーションを抑制し、触覚のオン・オフは触覚設定で独立制御する。

自動テストでは保存成功・失敗・無効操作の確認結果と下書き・FSRS・カードID・履歴保全を検証。実機の確認範囲は下記の記録に限定する。Issue #89の残る実機チェック項目を本人のiPhoneで確認するまでIssueをOpenに維持する。端末データの削除・初期化は不要。

2026-10-14実機確認: iPhone 15 Pro / iOS 27.0.1 (24A446) / Xcode 27.0 (27A266a)。署名付きDebugビルド・テスト専用ストアでの起動に成功。更新前にアプリコンテナをMacへ保全し、SQLite quick_checkは正常。テストストア起動前後で既存Study.store本体とWALのハッシュ一致を確認。既存UIテスト2件は自動操作モード有効化のタイムアウトで開始できず。

本人による手動確認: 「豊か」で答え表示・評価・Undoの重複振動なし、テスト用5枚終了後の達成画面で追加振動なし。今回修正した達成画面の誤発火・重複経路は実機で確認済み。標準との比較、オフ時の全イベント抑止、回答上限到達時の3連パターン、並び替えのドラッグ・キャンセル・正誤判定、遅延・不発、システム設定・VoiceOver・Reduce Motionとの組合せは未確認。
